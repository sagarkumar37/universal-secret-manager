# Universal Secret Manager

A small, self-hosted web UI for managing secrets in **GCP Secret Manager**, **Azure Key Vault** and **AWS Secrets Manager**. Sign-in uses your Google Workspace accounts.

It is built for teams that keep secrets as **bundles** (one vault secret holding a JSON object of keys), e.g. for External Secrets Operator. People can add, rotate, delete and restore keys **without ever seeing a secret value**.

## Features

- **Write-only values**: the UI and API return key names and versions, never values. Values are not logged or stored in the database.
- **Google sign-in** restricted to your Workspace domain(s), plus a per-user allow list with roles:
  - `viewer`: sees key names
  - `editor`: changes secrets
  - `admin`: manages users and reads the audit log
- **Safe writes**:
  - every change is a new vault version;
  - a change is refused if someone else edited the bundle meanwhile;
  - delete and restore need typed confirmation;
  - restoring an old version adds a new version, so history is never rewritten.
- **Audit log** in PostgreSQL. The app's database role can only append to it, never update or delete.
- **Pluggable vaults**: one interface, one file per provider. One instance can show several vaults.
- Responsive UI (desktop and phone), no build step, strict Content-Security-Policy.

## Architecture

```
browser ──► frontend (nginx: static UI, proxies /api and /auth) ──► backend (FastAPI) ──► vault provider (GCP / Azure / AWS)
                                                                        │
                                                                        └──► PostgreSQL (users, audit log)
init-migration: one-shot container that applies versioned SQL migrations before the backend starts
```

| Folder | Contents |
|---|---|
| `backend/` | Python 3.12, FastAPI, Authlib (Google OIDC), psycopg 3; providers in `usm/providers/` |
| `frontend/` | Plain HTML/CSS/JS served by unprivileged nginx |
| `db/` | PostgreSQL 16 config and backup script |
| `init-migration/` | SQL migrations and runner (checksummed; an edited, already-applied migration is refused) |
| `config/` | Example config (`config.example.yaml`) and the test config |
| `scripts/` | `init-secrets.sh` generates local runtime secrets |

## Quick start (Docker)

```bash
git clone https://github.com/<you>/universal-secret-manager && cd universal-secret-manager
./scripts/init-secrets.sh                      # creates ./secrets (git-ignored)
cp config/config.example.yaml config/config.yaml
# edit config/config.yaml, then:
#   secrets/google_client_secret   <- OAuth client secret
#   secrets/vault_credentials      <- e.g. GCP service-account JSON
docker compose up -d --build
```

The UI listens on `127.0.0.1:8080` by default. To change the bind address or port, set `USM_BIND` / `USM_PORT`. Then add HTTPS in one of two ways:

- **Behind your reverse proxy:** point the proxy at port 8080 and set `instance.base_url` to the HTTPS URL.
- **TLS on the host itself:** put the certificate chain in `secrets/tls.crt` and the key in `secrets/tls.key`, then run:
  ```bash
  COMPOSE_FILE=docker-compose.yml:docker-compose.tls.yml docker compose up -d
  ```
  This serves 443, and port 80 redirects to HTTPS. Change the ports with `USM_TLS_PORT` / `USM_HTTP_PORT`.

### Google OAuth client

In Google Cloud Console → APIs & Services → Credentials, create an **OAuth client ID** of type *Web application*:

- **Authorized redirect URI:** `https://<your-host>/auth/callback`
- **Consent screen:** *Internal*, so only your Workspace accounts can sign in.

The first admin(s) come from `auth.initial_admins`. Add everyone else in the UI under **Users**.

## Configuration

Non-secret settings live in `config/config.yaml` (see the example). Secrets are read only from files in `./secrets`, mounted as Docker secrets:

| File | Purpose |
|---|---|
| `db_owner_password`, `app_db_password`, `database_url`, `session_key` | generated by `init-secrets.sh` |
| `google_client_secret` | OAuth client secret |
| `vault_credentials` | provider credentials (GCP service-account JSON) |

Run **one instance per trust boundary**, e.g. separate instances for non-prod and prod, each with credentials that can reach only its own vault.

### Vault permissions

| Provider | Minimum permissions |
|---|---|
| GCP | `roles/secretmanager.viewer`, `secretAccessor`, `secretVersionAdder` on the project |
| Azure | Key Vault Secrets Officer (or get/list/set) |
| AWS | `secretsmanager:ListSecrets`, `GetSecretValue`, `PutSecretValue`, `ListSecretVersionIds` |

Azure and AWS need extra Python packages. Build with:

```bash
USM_EXTRA_PACKAGES="azure-identity azure-keyvault-secrets boto3" docker compose build backend
```

## Adding a vault provider

1. Create `backend/usm/providers/<name>.py` with a class extending `VaultProvider`, implementing `location`, `list_bundles`, `_read`, `_write` and `versions`.
2. Register it in `backend/usm/providers/__init__.py`.
3. Use `provider: <name>` in the config.

No UI or API changes are needed.

## Testing

```bash
# full stack with an in-memory vault and dev login (never use dev login for real vaults)
USM_PROJECT=usmtest USM_PORT=18080 USM_CONFIG_FILE=./config/test.yaml docker compose up -d --build

# unit + end-to-end API tests
docker run --rm -u root --network usmtest_default -v "$PWD/backend:/src" -w /src \
  -e USM_E2E_URL=http://frontend:8080 usmtest-backend sh -c "pip install -q pytest && pytest -q tests"

# browser smoke test + screenshots (desktop and phone)
docker run --rm --network usmtest_default -e USM_UI_URL=http://frontend:8080 \
  -v "$PWD/frontend/tests:/t:ro" -v "$PWD/out:/out" mcr.microsoft.com/playwright/python:v1.49.1-noble \
  sh -c "pip install -q playwright==1.49.1 && python /t/screens.py /out"
```

## Logs

Containers use the Docker daemon's default log driver. For time-based retention, e.g. 60 days, send logs to journald:

```bash
# /etc/docker/daemon.json
{ "log-driver": "journald", "log-opts": { "tag": "docker/{{.Name}}" } }

# /etc/systemd/journald.conf.d/retention.conf
[Journal]
Storage=persistent
MaxRetentionSec=60day
MaxFileSec=1week
SystemMaxUse=3G
SystemKeepFree=5G
```

Then restart journald and Docker, and recreate the containers with `docker compose up -d --force-recreate`. `docker compose logs` keeps working; `journalctl -t docker/usm-backend-1` works too.

## Operations

- **Backup:** `./db/backup.sh /path/to/backups`, a daily `pg_dump` of users and the audit log with 30-day retention.
- **Audit retention:** `./db/retention.sh` deletes audit rows older than `USM_AUDIT_RETENTION_DAYS` (default 365) and records each purge in the audit log. Run it daily, e.g. from a systemd timer or cron. Users and roles are never purged.
- **Rotate the app DB password:** change `secrets/app_db_password` and `secrets/database_url`, then run `docker compose up -d migrate backend`.
- **Upgrade:** `git pull && docker compose up -d --build`. Migrations run automatically.
